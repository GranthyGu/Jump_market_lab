# 串联测试

编译一次 `./tests/build.sh`，以后直接运行 `./tests/integration/run.sh`。使用正式 Gateway、独立 Engine 进程、Publisher 及行情观察客户端，不依赖手工部署。

| Case | 具体情形 | 检查内容 |
| --- | --- | --- |
| I01 | 新恢复状态机先确认 TCP 基准；UDP 批次 2 先到、1 后到；旧 TCP 回复迟到；连续后续包使缓存超限 | 200 ms 等待；补齐后立即推进并取消旧任务；迟到 TCP 不覆盖状态；超限清空 pending 但保留最高已见版本，不能误报 SYNCED |
| I02 | 64 商品、2 个真实分片；每商品 Alice Buy 100×10，Bob Sell 100×6，最后 Alice 撤剩余 4 | 两个参与者均先收到正确接受，再收到正确 Trade/OrderUpdate；双方成交 ID、价量与时间一致；Alice 登录快照是所有剩余 4；Publisher 全商品查询先为 10、再为 4、最后为空 |
| I03 | 同样交易序列扩展至默认规模：1000 商品、4 个真实分片，每片 250 商品 | 每个商品确实路由至负责分片；跨分片订单号唯一；1000 笔实际成交及双方通知完整；全片登录快照与公开行情保持一致 |
| I02/I03 压力阶段 | 已清空交易后，8 个用户以 16 请求窗口进行每人 20 轮新单/撤单；Publisher 保持采样；独立线程持续 TCP 查询，另一个线程接收组播 | 5120 条计时请求逐条核对；没有丢失/重复；最终重登无挂单；直接查询所有 Engine 行情接口也为空；确认 UDP 接收和 TCP 查询确实并行推进 |
| I04 | 两个真实分片和 Publisher；代理转发真实组播到另一组，故意丢掉商品 1 的第 2 批；运行正式 observe；随后停 Publisher 再启动 | 自动 TCP 初始化和丢包恢复；恢复后的量等于真实挂单；静默达到 STALE；重启后 epoch 改变并被客户端确认；挂单仍可通过交易连接撤销，公开状态最终为空 |
| I05 | 同 epoch 的自适应快照跨过缺失批次；快照之后的增量先到；周期轮次只收到快照；随后收到增量和空增量 | 快照重建基准并使旧 TCP 请求失效；后续缓存增量正常衔接；周期快照无需同批增量；空增量推进序号与时间戳但不改变订单簿 |
| I06 | 同一真实分片同时启用 TCP 与共享内存行情；订单完成后两种来源并发读取，再停止分片 | 两种来源均看到正确数量和全部品种；无新订单时仍能完成快照请求；停止时不会等满邮箱的请求超时 |

I04 只丢一个特定真实 UDP 消息，不构造假行情。TCP 恢复仍直连真实 Publisher；因此客户端可因缺口或静默阈值触发恢复，不要求固定由某一条检测路径先启动。I01 补充可控的竞态和缓存边界，避免仅凭端到端日志推断内部任务失效逻辑。

性能分别报告串行接受 RTT、主动订单从发送至收到完整成交状态的延迟，以及 Publisher 同时工作时的并发新单/撤单 RTT。每个指标均保留样本与计时口径；启动部署、等待每秒行情采样、故障检测和服务重启不混入订单 RTT。并发指标的吞吐分母包含该阶段用户登录和最终对账。

串联用例允许不同分片的实时通知交错，按 orderId/requestId 对账，不假设存在跨分片全局顺序。Publisher 是每秒采样，因此交易完成后等待它提交相应的新批次再核对公开状态；不是逐笔即时发布。

报告、配置及 Gateway/Engine/Publisher/observer 日志全部保留在脚本打印的结果目录。任何缺失/重复通知、数量不一致、错误路由、恢复失败或超时均返回非零。演示使用本机动态端口和 loopback 组播，不声称完成跨机器验收。
